# Repository Inventory

The full file-by-file inventory is generated by `scripts/inventory.py` and uploaded by the **inventory** GitHub Actions workflow as the artifact `KnockDesk-Repository-Inventory-<commit-sha>`.

Open [GitHub Actions](https://github.com/OpKnock/KnockDesk/actions), select a successful **inventory** run for the commit you want to inspect, and download its inventory artifact. The report lists each tracked/checked-out repository file and its byte size, including the downloaded Git LFS payloads.

## Generate locally

From the repository root, first fetch the binary payloads if you need their real sizes:

```powershell
git lfs install
git lfs pull
python scripts/inventory.py
```

The command writes `staging/INVENTORY.md`. The `staging/` directory is ignored by Git, so the generated file list and large payload sizes do not accidentally become a source commit. The script excludes the Git object database itself; it inventories the checkout, not the commit history.

The inventory is a file/size listing, not a source recovery report. See [Build and source map](BUILD_AND_SOURCE_MAP.md) for the distinction between editable source, generated bundles, V8 bytecode, native binaries, and external services.
